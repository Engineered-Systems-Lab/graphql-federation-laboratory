## Choices recorded

- **Fields and names** follow the contract's element names and exact enum tokens. The contract's `Status` and `Location` are `MissionStatus` and `MissionLocation` because the graph is shared. The contract's `title` is included although the scope list omitted it. The lead developer saw the field list in the preview.
- **Credits and the stardate are strings** carrying the contract's canonical decimal text, never a binary float and with no scalar of our own; `priority` and `durationHours` are `Int`.
- **The XML parser** is the JDK's namespace-aware DOM parser; a document with any DOCTYPE is refused, which removes external entities, external DTDs and entity expansion in one rule. The tests send an external general entity, an external parameter entity, an external DTD, an internal entity bomb and an XInclude against a tripwire server and assert nothing is fetched. A body is accepted only if it reads as the contract says; anything else is UPSTREAM_BAD_RESPONSE.
- **Not-found is data:** a 404 with the XML code MISSION_NOT_FOUND gives a null mission and no errors entry; the bodyless 404 of an unknown path is UPSTREAM_BAD_RESPONSE; INVALID_MISSION_ID and INVALID_REQUEST (a filter value) are BAD_USER_INPUT; a 5xx, a timeout or no answer is SERVICE_UNAVAILABLE.
- **Paging** translates offset and limit (default 20, maximum 100) into the page size from 1 to 50 that covers the window with the fewest calls, then slices; an offset past the end is an empty list; a page is all or nothing with one errors entry and no call after the first failure. This choice of page size is the worker's, shown to the lead developer in the preview.
- **An id that cannot be one path segment** (a slash or backslash, empty, `.` or `..`) is BAD_USER_INPUT without a call. The real-service gate showed that the service's container answers such an id with something that is not INVALID_MISSION_ID, which would have been blamed on the service.
- **The shared library** gained one overload, `Outcomes.fromCall` with a reader of the service's error code, because the Missions errors are XML. The parent pom lists the new module, which forced the Assets and mapping Dockerfiles and their ignore files, packaging tests and READMEs to copy the pom and the sources of every adapter, so that a later adapter changes only the parent's module list. The Assets README carries the port plan of the lead developer's two corrections (routers 8170, 8171 and 8172, mapping adapter 8190, 8180 kept free).
- **Packaging** follows the Assets adapter, with the repository root as the build context so that the offline tests read the real contract fixtures and the released dataset 1.0 instead of a copy. Versions and base image digests are those of the Assets adapter (resolved 2026-10-16). Container limits are provisional.
- **Found:** federation-jvm 5.4.0 lists a `resolvable: false` type in the `_Entity` union, as the stub of experiment 2 did; the adapter answers an `_entities` request for it with INTERNAL_SERVER_ERROR and a router never sends one.
- **Checks:** the profile `federation-adapter-runtime` gained `federation-missions-offline`. The service stage needs the stopped Oracle container, so it is not part of the profile and is run deliberately.
