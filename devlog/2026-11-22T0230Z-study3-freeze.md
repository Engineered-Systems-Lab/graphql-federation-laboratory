## The price table and the two code Jobs

Both pricing pages were read on 2026-11-21 (UTC). For claude-sonnet-5-5 and gpt-6.1-sol, input 2.00, cached read 0.10 and output 10.00 dollars per million tokens, and Anthropic's five-minute cache write 2.50, are what `prices.json` (dated 2026-10-20) held.

The OpenAI page also lists cache-write prices: 2.50 for 30 minutes and 5.00 for 12 hours, where `prices.json` had 0.00. Asked whether that is a change that stops the freeze, the lead developer answered "Not a change, go on". Then a review found that the harness's OpenAI client never read `usage.input_tokens_details.cache_write_tokens`, where OpenAI's prompt-caching guide says the Responses API reports written tokens. So a GPT run's cost would have priced written tokens at the input rate. The lead developer routed that to a code Job before the freeze ("(a), code Job first"). Two Jobs landed:

- **`study3_openai_cache_write` (`93e0663`):** the OpenAI client counts cache writes, and the runner reads a new dated table, `prices-20261121.json`, with gpt-6.1-sol's cache write at 2.50, the default 30-minute price.
- **`study3_openai_long_context` (`c5c4d96`):** each request is priced on its own. A gpt-6.1-sol request whose input is above 272,000 tokens pays the long-context rates for the full request: input 4.00, cached read 0.20, cache write 5.00 and output 15.00. Claude has no such tier.

The plan's section 14 and the freeze record state both rules. The first record's sentence that the harness does not count OpenAI cache writes is kept and marked superseded, and so is the price read's note on it.
