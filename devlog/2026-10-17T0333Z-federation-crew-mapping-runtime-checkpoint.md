## Choices recorded

- **The process is the lead developer's order of 2026-10-16.** For each reference of the recipe: the mapping exceptions table (every target must exist in the pinned v2 snapshot, and it never names v1; a match stops the process); an exact name in the pinned v2 snapshot; an exact name in the pinned v1 release or the migration exceptions table (the person must be migrated); otherwise a failure. More than one match fails and reports every match, never a pick. Live mode never runs the migration step and ends in UNMAPPED; the static build fails. Every input is pinned by hash in `pins.json` and the release repeats the pins, so a run refuses to start when one differs.
- **The migration.** A migrated person keeps the number of the v1 id (CRW-1048 becomes PRS-1048); people already in v2 keep their ids. The seven added are William Riker, Geordi La Forge, Beverly Crusher, Deanna Troi, Reginald Barclay, Worf and Miles O'Brien (PRS-1048, 1049, 1053, 1054, 1057, 1058, 1100). Picard (PRS-0001) becomes a mapping exception; Data and Wesley match by name. Supervisors are remapped (Riker reports to Picard, La Forge and Worf and O'Brien to Riker, Barclay to La Forge). The clearance follows the lead developer's rulings: by rank (CAPTAIN TOP_SECRET, COMMANDER and LIEUTENANT_COMMANDER SECRET, the rest NONE) and at least SECRET for department SECURITY, so Worf is SECRET. The snapshot is written by the migration command, keeps the seven existing records byte for byte, and the XSD, WSDL and the two released snapshots are unchanged.
- **Exceptions.** Five people do not match the recipe name exactly (the recipe writes Riker, La Forge, Troi, Barclay and O'Brien), so each has a migration exception and, after the migration, a mapping exception with the migrated id; Picard has a mapping exception only. A mapping exception whose target is not in the source snapshot is accepted by the migration only when the same run creates exactly that id.
- **Release 1.1 is a MINOR.** `assets.json` is the 1.0 file byte for byte, `crew.json` is the full table of the ten references with their controlled cases (NORMAL: C-85, C-120; EXCEPTION: C-71; MIGRATED: the other seven), and the manifest adds the snapshot `personnel-v2-small-003` to the checked-against list. Release 1.0 is untouched (its two hashes are pinned in a test). File names stay `assets.json` and `crew.json`, by the lead developer's ruling, to avoid a 2.0 for names.
- **Checks.** The acceptance test `test_crew_mapping.py` was written first, with the expected table of the ten references typed by hand from the released files. The release check now compares `crew.json` with what the process builds, checks an older release only against what it lists, and makes the newest release name the newest Personnel v2 snapshot. The container gate script of Personnel v2 no longer assumes seven members. The three classification rows of the new folder are in the table.
- **Found, not decided:** the first prepare failed on one check only, `federation-router-apollo-stack`, because the committed supergraph carries the schema comments of the mapping adapter, which this change edited; the transaction was abandoned, the supergraph patched with exactly the diff the gate printed, and a second preview and go taken.
