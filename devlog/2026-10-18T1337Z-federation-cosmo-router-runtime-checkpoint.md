## Choices recorded

- **The design is the lead developer's, in nine points.** Self-hosted router with local composition, to compare like with like for this round; the newest router and `wgc` at build time, pinned by digest; the execution config committed only if byte-reproducible, with a freshness test; the smallest error-passthrough setting; the same 5 second timeout; port 8171 and the same compose with a router switch; the licence re-checked; the telemetry setting verified; and the live effort capture. The Job record holds their words.
- **The worker added one setting: `retry.enabled: false`.** Cosmo retries a failed subgraph request by default (5 attempts), and a dead adapter then answered after 5.1 s in one run and 21.0 s in the next. The Apollo router did not retry in its measured runs. The setting keeps the two timeouts equivalent; it is the lead developer's to keep or change.
- **The settings object was not enough.** It declared three settings and only Apollo had used it. Cosmo writes the entry for a dead adapter itself: no `extensions` at all (no code, no `service` key), the subgraph named only in the message, and one entry per failed fetch where Apollo gives one per reference. Two declared settings were added (`subgraph_in_message`, `entries_per`) with Apollo's values as defaults. The Apollo stack gate passed the same assertions in the same seal.
- **Findings, each a fact of one run on stub data.** Cosmo nulls only the dead subgraph's fields with the nullable `resolution` (the key matrix row). `mode: pass-through` is the smallest setting that gives `extensions.code` at the top level. Cosmo's composition and Rover's agree on the lab's schemas, including the two-field `@requires` with an enum from another subgraph, but Cosmo's output depends on the order of the subgraphs and Rover's did not. Cosmo found a restarted adapter again by itself (16.4 s in the gate), where Apollo needed a restart. A request with no release is HTTP 200 under Cosmo (HTTP 400 under Apollo). The licence at the pinned source is Apache-2.0 and `COSMO_TELEMETRY_DISABLED=true` turns the usage tracking off for the router and for `wgc`.
- **One stack change.** The Cosmo router is a service of the existing compose file under the profile `cosmo`, so the file without the profile is the Apollo stack as before; `FEDERATION_ROUTER=cosmo` in the start script composes with `wgc` and starts it. Apollo's dry run is unchanged and tested.
