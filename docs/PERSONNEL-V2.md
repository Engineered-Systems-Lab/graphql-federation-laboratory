# Personnel v2

Status: implementation prepared for lead developer review; not frozen or committed by this work. This specification and the sibling executable WSDL/XSD define v2. The earlier [identity design](PERSONNEL-V2-MISSIONS-IDENTITY-DESIGN.md) remains dated provenance. G018/G019/D021/D022 apply. Frozen v1 and all v1 datasets remain unchanged.

## Model and ownership

Personnel owns personnel identity, descriptive facts, duty status and reporting. PersonnelMember contains, in order, personnelId, displayName, positionTitle, dutyStatus, then exactly one required xs:choice branch: crewDetails or civilianDetails. All application elements are namespace qualified, non-nillable, ordered and closed to unknown fields/attributes. Any xsi:nil attribute is rejected, even false. Omission alone means absence/default. String whitespace is preserved; enums and IDs are case sensitive. DisplayName/PositionTitle remain nonblank 1..100 XML characters, using v1 scalar rules.

personnelId is exactly PRS-0001 through PRS-9999; PRS-0000 is invalid. IDs permanently identify the same person, never reused or inferred from another system, and survive subtype changes. CrewDetails has rank, department, securityClearance, then optional supervisorPersonnelId. CivilianDetails is an empty complex type: civilians need no invented rank, department, clearance or reporting fields.

Rank: CAPTAIN, COMMANDER, LIEUTENANT_COMMANDER, LIEUTENANT, ENSIGN, CHIEF_PETTY_OFFICER, CREWMAN. Department: COMMAND, OPERATIONS, ENGINEERING, SCIENCE, MEDICAL, SECURITY, FLIGHT_OPERATIONS (unchanged from v1). SecurityClearance: NONE, SECRET, TOP_SECRET. DutyStatus: ACTIVE, ON_LEAVE, INACTIVE, DECEASED. There is no contract-enforced status-transition matrix; this read-only roster is not a lifecycle service. Status/rank/clearance do not by themselves establish mission eligibility or application authorization.

An omitted supervisor means no supervisor recorded. A present reference resolves to a PersonnelMember in the same snapshot (including a civilian); no subtype, rank, clearance, department or status eligibility restriction is invented for the target. Self-reference and cycles fail startup. Multiple roots, inactive supervisors and cross-department reporting remain valid. Native Personnel never consumes Missions classifications or suffix-based mappings. [Semantic disagreement](../project-governance/CONSTRAINTS.md#bounded-context-semantic-disagreement) is preserved, even if a canonical model could remove it.

## Mechanical choices

Separate component: `uss-enterprise/personnel-v2`. Namespace: `urn:graphql-federation-lab:personnel:v2`. Endpoint: `/soap/personnel-v2`, default loopback port 8082. These distinguish v2 while leaving v1 deployment intact. SOAP 1.1 HTTP document/literal uses OperationNameRequest/Response wrappers and namespace:OperationName SOAPActions. The binding WSDL has no service; deployment.wsdl imports it and adds only service/port/address metadata. Generated JAXB/JAX-WS code stays in ignored target/.

| Operation | Request children in order | Response children in order |
| --- | --- | --- |
| GetPersonnelMember | personnelId | datasetVersion, personnelMember |
| ListPersonnelMembers | optional department, dutyStatus, offset, limit | datasetVersion, personnelMember (0..100), totalCount, offset, limit, hasMore |

Both operations return the same PersonnelMember. List defaults are offset=0, limit=20; limit is 1..100, offset 0..2147483647. Filters combine with AND. Omitted filters include civilians and all statuses; department matches only records with crewDetails and that department. No subtype, Missions, rank or clearance filter is added. Sort personnelId ascending before pagination. totalCount counts all matches; return min(limit,max(totalCount-offset,0)) records. hasMore is exactly offset + returnedCount < totalCount, using overflow-safe arithmetic; beyond-end offsets return an empty page. Get includes all statuses. Numeric whitespace/lexical forms follow v1 XSD integers. No coercion, trimming, clamping or snapshot tokens.

Every success starts with datasetVersion, an opaque immutable content identifier, not time/freshness. Consumers compare every page and discard accumulated pages/restart at offset 0 on change. Snapshots never merge. Content changes require new versions; breaking contracts require new namespaces.

PersonnelServiceFault contains code, nonblank message (1..512 XML characters), optional field. Codes InvalidRequest and PersonnelNotFound map to SOAP Client; ServiceUnavailable/InternalError to Server; declared faults use HTTP 500, success 200. Unknown well-formed ID gives PersonnelNotFound with field=personnelId. Invalid fields are rejected before profile execution/JAXB can discard them; field is omitted when unknown. Malformed XML, DTD/entities and unsupported SOAP versions remain protocol failures, without a promised business detail. Unexpected service errors are sanitized. Profiles normal/slow/unavailable retain v1 behavior: slow waits 2000 ms after request validation, including lookup misses; unavailable fails valid requests. Restart restores selection.

## Snapshots and runtime

Two explicitly registered seven-record synthetic snapshots are in datasets/. Both have Picard PRS-0001, Data PRS-0002, Guinan PRS-0003, Mara Venn PRS-0004, Elias Renn PRS-0005, Tasha Yar PRS-0006, Wesley Crusher PRS-0714. These are authored local v2 assignments, not a v1 migration or Missions mapping. No numeric-suffix inference is used. The snapshots are illustrative lab facts, not episode chronology. They cover all statuses and clearance values; no real-person record is created.

personnel-v2-small-001 has Wesley as a civilian Student; personnel-v2-small-002 has the same PRS-0714 as crew ENSIGN / OPERATIONS / NONE / Acting Ensign, reporting to Data. All other records are identical. Default is 002; 001 stays independently selectable. Each is a complete list response, offset 0, limit 20, hasMore false. Hashes are pinned in Dataset.java, exact raw bytes with Git -text attributes. D017 LF normalization remains v1-only. Load/hash/schema/count/unique-ID/reporting checks run before endpoint publication; failure terminates startup without fallback. Records are defensively deep copied. No external dataset paths, hot reload, scans or runtime generation.

personnel-v2-small-003 (14 records, a small snapshot) keeps the seven records above byte for byte and adds the seven people of the Missions crew whom Personnel v2 did not hold: PRS-1048 William Riker, PRS-1049 Geordi La Forge, PRS-1053 Beverly Crusher, PRS-1054 Deanna Troi, PRS-1057 Reginald Barclay, PRS-1058 Worf and PRS-1100 Miles O'Brien. They were migrated from the legacy crew release crew-v1-large-003 by the process of federation/personnel-mapping (the federation layer, not Personnel): a migrated person keeps the number of the v1 identifier (CRW-1048 becomes PRS-1048), supervisors are remapped to PRS identifiers, and the clearance, which v1 does not have, is set by rank (CAPTAIN TOP_SECRET; COMMANDER and LIEUTENANT_COMMANDER SECRET; every other rank NONE; department SECURITY at least SECRET). The v2 contract (XSD, WSDL) is unchanged and 001 and 002 stay as they are. The default stays 002; 003 is selected with PERSONNEL_DATASET_VERSION. The hash is pinned in Dataset.java as for the others.

personnel-v2-large-004 (1,000 records) is the large snapshot. It holds the 14 records of personnel-v2-small-003 byte for byte, the other 787 people of the legacy crew release crew-v1-large-003 and 199 civilians. The 787 were migrated by the batch mode of the same federation process (federation/personnel-mapping): for each of the 800 people of the release, a person already in Personnel v2 by exact name keeps the v2 identifier and record (13 people, among them Picard PRS-0001, Data PRS-0002, Guinan PRS-0003 and Wesley PRS-0714), and every other person keeps the number of the v1 identifier (CRW-1048 becomes PRS-1048), with supervisors remapped to PRS identifiers and clearance by the same rank rule as for 003. A v1 civilian becomes a civilian record, and because a civilian record holds no reporting fields, the supervisor of the 19 migrated v1 civilians is not carried over. The 199 civilians (PRS-3001 to PRS-3199) are people on the ship's roster without rank, department or clearance: four are inspired by the television series (Alexander Rozhenko, Keiko O'Brien, Molly O'Brien and Mot; the dataset states no episode facts about them) and the rest are generated families, residents and civilian staff with invented names, by a deterministic standard-library script with a fixed seed (federation/personnel-mapping/civilians.py). The generated ones are synthetic, and the manifest records the seed, the algorithm, the hash of the generator and the pinned inputs. The contract (XSD, WSDL, paging rules) does not change, and 001, 002 and 003 stay as they are. The contract returns at most 100 members per response, so this snapshot is a package of ten pages (datasets/personnel-v2-large-004/page-000.xml to page-009.xml, each a valid list response of 100 members with its own offset and hasMore) plus manifest.json. Dataset.java pins the raw bytes of the manifest and of every page, and startup also checks the paging fields of each page, one strictly increasing personnelId order across all pages, the count, unique identifiers and the reporting graph over the whole snapshot before the endpoint is published. The default stays 002; 004 is selected with PERSONNEL_DATASET_VERSION. Snapshots are still never merged.
