# Project Decisions

The project's own standing decisions. Each decision has an ID with the prefix D and three digits (any free number; the framework's decisions carry the prefix G and live in [the framework's registry](../governance/DECISIONS.md), so the two series cannot collide), a date, a status and the decision itself. Supersede a decision explicitly rather than silently rewriting it. The rules a decision creates go to [Project Constraints](CONSTRAINTS.md).

For the evidence audit and the reasons behind each decision, see [Why the project's decisions exist](RATIONALE.md) (non-normative). Every decision and every dated extension has one row in its audit table and one entry there, recorded in the same change that makes the decision effective.

## D016 - Crew & Personnel Java SOAP Service v1 (2026-09-30, Accepted)

Use Java 17, Apache CXF 4.2.3, Maven, and WSDL-first JAX-WS for the standalone Personnel service. This represents a traditional enterprise SOAP integration: Java 17 is old enough to be believable while remaining the supported baseline of the chosen CXF line ([CXF 4.2.3 prerequisites](https://cxf.apache.org/cxf-423-release-notes.html)). Do not add Spring Boot or Spring Web Services. Containerization is reproducible lab deployment infrastructure, not necessarily part of the fictional original legacy system's history.

The frozen WSDL/XSD generate JAXB types and the JAX-WS interface during Maven `generate-sources`; generated Java remains under ignored `target/`. Runtime publication uses a separate deployment descriptor that imports the frozen binding and adds only service/port/address metadata. It does not replace or edit the frozen contract. CXF's generated Java parameter style is BARE because the committed wrapper names include `Request`; this is a Java mapping, not a change to the single-wrapper document/literal wire format.

Default to `crew-v1-small-002`; explicitly select `crew-v1-small-001` for the original six-record benchmark or `crew-v1-large-003` for the released 800-person package. Startup admits only these explicitly registered, hash-checked immutable datasets, never a union of versions. Profile selection is independent of dataset selection. Validate payloads before JAXB binding and profile execution, and reject unready datasets before publication. The original 2026-09-30 policy admitted only 001/002 and called 002 the latest canonical snapshot; the 2026-10-01 extension below supersedes that registered set, retaining the default.

Use Maven 3.9.11 / Temurin JDK 17.0.17+10 for the tested container build and Temurin JRE 17.0.20.1+1 for deployment. Both image bases are pinned by digest in the Dockerfile. Compile with `--release 17`. Enable the JDK's XML code-point length option so the implementation honors the frozen XML-character limits instead of counting UTF-16 units. See the component README and [runtime validation report](../docs/CREW-PERSONNEL-JAVA-V1-VALIDATION.md).

### D041 page totals revision (2026-11-04, Accepted scope)

- **Page fields beside the lists.** The Missions and Assets adapters (1.0.0 to 1.1.0) add `missionsPage` and `assetsPage`, with the lists' filters, offset and limit, returning `MissionPage` and `AssetPage`: `items`, `totalCount`, `offset`, `limit` and `hasMore`, shaped like the graph's `PersonnelPage`.
